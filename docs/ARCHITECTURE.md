# 아키텍처

## 1. 원칙

1. **완전 로컬**: 네트워크 코드를 컴파일하지 않습니다. 모델, 지식, 기록은 모두 사용자 컴퓨터에만 있습니다.
2. **필요할 때만 동작**: 모든 기능은 모듈입니다. 쓰는 순간에만 메모리를 차지하고, 쉬면 내려갑니다.
3. **하나의 메모리 상한**: 프로젝트에 인스턴스가 수백 개여도 큰 데이터는 프로세스당 하나인 memopro 런타임의 상한 안에 있습니다.
4. **AI는 검증된 동작만 합니다**: 모든 변경은 `ActionExecutor`를 거칩니다. 범위, 허용 목록, 보호, 안전 한계를 검사하고, 변경마다 기록이 남습니다.

## 2. 플러그인 안의 플러그인, 연결된 인스턴스

DAW는 플러그인에게 자기 입력 오디오만 줍니다. 그래서 두 가지 방식을 씁니다.
- 사용자가 허용한 플러그인을 Sound Manager 안에서 **호스팅**합니다(`HostedChain`). 오디오 스레드는 try-lock 후 처리하고, 체인 교체 중에는 원음을 통과시킵니다.
- 모든 채널의 인스턴스를 같은 프로세스 안의 `SessionHub`가 하나의 `MixSession`으로 묶습니다. 범위 규칙은 이렇습니다.
  - 트랙: 자기 자신
  - 버스: 자신 + 하위 채널
  - 마스터: 전체

## 3. 메모리: memopro

`smix::mem::Runtime`이 memopro C ABI(`mp_*`)를 감쌉니다. Rust crate `memopro-c`를 cargo로 빌드해 정적 링크합니다.

| 데이터 | memopro 버퍼 종류 | 메모리가 부족할 때 |
|---|---|---|
| 플러그인 지식(프로파일 JSON) | 메모리 버퍼 | 무손실 압축 |
| 믹스 기록의 플러그인 상태 전체(해시로 중복 제거) | 메모리 버퍼 | 무손실 압축 |
| 절전 중인 플러그인 상태 | 메모리 버퍼 | 무손실 압축 |
| 언어 모델의 시스템 프롬프트 KV 상태(모델이 내려가 있을 때) | 메모리 버퍼 | 무손실 압축 |
| 악기 인식 모델 가중치 | 파일 영역 버퍼 | 내렸다가 다이제스트를 검증하며 다시 읽음 |

- 상한을 넘는 요청은 거절됩니다(`refusals`). 디스크 스왑은 하지 않습니다(`written_bytes = 0`).
- 언어 모델 가중치는 llama.cpp가 mmap으로 읽습니다. 파일 기반 깨끗한 페이지라 OS가 내렸다가 다시 읽을 수 있고, 복사본을 만들지 않습니다.
- memopro를 쓸 수 없을 때(cargo 없음, Windows)는 같은 인터페이스의 대체 할당기를 씁니다. 상한 계산과 파일 버퍼 재읽기는 하지만 압축은 하지 않습니다.

메모리 위계는 이렇습니다.
1. 인스턴스(채널마다): 분석기(약 50 KB)와 체인 메타데이터
2. Engine(프로세스당 하나): memopro 런타임, 모듈 관리자, 모델
3. 호스팅 플러그인: 쓰지 않으면 절전합니다. 30초 이상 바이패스된 플러그인이 대상이고, 선택하면 2분 이상 무음인 채널도 포함됩니다. 절전 중 상태는 memopro에 두고, 다시 켜거나 소리가 돌아오면 같은 상태로 다시 만듭니다.

## 4. 모듈 (`smix::modules::ModuleManager`)

| 모듈 | 언제 로드 | 언제 해제 |
|---|---|---|
| 청음(분석·지각) | 항상(인스턴스마다, 가벼움) | - |
| 악기 인식 모델 | 이름 후보를 만들 때 | 60초 유휴 |
| 요구·문맥 추론(LLM) | 채팅 요청 시(로딩 ETA 표시) | 180초 유휴(설정 가능) |
| 플러그인 지식 | 검색, 채팅 문맥, 프로파일링 결과 저장 시 | 120초 유휴 |
| 레퍼런스, 자동 믹스, 분석 그래프, 기록, 분석기, 절전 | 스위치 (분석 그래프는 창이 보일 때만 DSP가 계산) | 30초 유휴 |

`acquire()`는 Lease를 돌려주고, Lease가 살아 있는 동안 모듈은 내려가지 않습니다. 모듈 메모리 상한을 넘으면 가장 오래 쉰 모듈부터 내린 뒤 새 모듈을 올립니다. 사용자가 끈 모듈은 절대 올라오지 않습니다.

## 5. 듣기 → 이해 → 행동 → 다시 듣기 (`MixAssistant`)

```
사용자 문장
  └ 추론 모듈: 로컬 LLM(llama.cpp, GBNF 문법으로 JSON 강제) → 실패하면 규칙 기반 이해기
       입력: 세션 상태(채널·역할·지각 요약·보호·스타일) + 레퍼런스 묘사 + 지식(RAG) + 최근 대화 + 열린 질문
  ├ view → 분석 그래프 열기 / command → 되돌리기, 전체 믹스, 레퍼런스 매칭, 피드백 …
  ├ 모호함 → 되묻기(선택지 버튼, 직접 입력 가능)
  └ 목표(goal) + 대상 → RecipeEngine이 실제 플러그인 파라미터 변경으로 번역
        → apply (기록 스냅샷) → 보호된 부분은 '직접 바꿔 주세요' 요청
        → 4초 뒤 다시 듣기: 측정상 목표 방향으로 움직였는가?
             아니면 0.5배 한 단계 더 (최대 1회) → 그래도 결과를 사용자에게 물음
             맞으면 "어떠세요?" [좋아요 · 더 · 덜 · 되돌리기] (40초 무응답 = 유지)
```

- 전체 믹싱: 트랙 → 버스 → 마스터 순서로 채널마다 스타일을 묻습니다. 25초 무응답이나 건너뛰기면 AI 기본 스타일입니다(레퍼런스가 있으면 레퍼런스 기반, 없으면 들리는 문제 교정). 스타일을 적용한 뒤 자동 믹스가 레벨과 톤을 계속 다듬습니다.
- 이름 요청: 이름이 의미 없고 역할을 모르는 채널마다 한 번씩, 한 번에 하나만 묻습니다. 악기 인식 모델의 후보를 버튼으로 보여줍니다. 요청 문장("make the kick tighter")은 이름으로 오인하지 않습니다.
- 스레드: `AssistantWorker`가 대화와 LLM을 별도 스레드에서 돌립니다. 믹스에 닿는 호출은 모두 메시지 스레드로 마샬링하고, 세션은 200 ms 캐시된 복사본을 씁니다. 인스턴스가 삭제되면 `alive` 플래그로 안전하게 끊깁니다.

## 6. 플러그인 지식 (요구사항 4)

`SoundManagerProfiler`(별도 프로세스)가 플러그인마다 다음을 측정합니다.
- 핑크 노이즈: 10개 대역 레벨, 전체 레벨, 스테레오 폭
- 드럼 히트: 크레스트 팩터(압축/트랜지언트)
- 임펄스: 150 ms 이후 에너지(리버브/딜레이 꼬리; EQ 링잉은 제외)
- 1 kHz 사인: 2~6차 배음(새츄레이션)

관련성이 높은 파라미터(최대 48개)를 0.1과 0.9로 바꿔 차이를 기록합니다. 영향이 없는 파라미터(GUI Zoom 등)는 민감도 0입니다. 측정된 동작으로 실제 종류를 판별하며, 순서는 잔향 → 왜곡 → 스펙트럼 → 다이내믹 → 폭입니다.

결과는 JSON lines(`knowledge.jsonl`)로 저장되고, 메모리에서는 memopro 버퍼 + 작은 역색인입니다. 검색은 BM25이며 한국어는 음절 바이그램, 영어는 단어 단위입니다. 한국어 믹싱 용어("단단", "치찰" 등)를 영어 파라미터·종류 단어로 잇는 동의어 표도 씁니다. 헬퍼가 크래시하면 그 플러그인을 '분석 실패'로 기록하고 나머지를 이어서 분석합니다.

## 7. 레퍼런스 스타일 (요구사항 2)

`GenreProfile`(`smix_learn_mix`)은 곡마다 대역별 에너지를 0.4초 프레임으로 나눕니다. 그리고 "완성 믹스 = 원본 트랙 에너지의 비음수 가중합"을 대역마다 NNLS(projected gradient)로 풉니다. 음원들은 서로 거의 무상관이라 에너지가 더해진다고 볼 수 있습니다. 대역별 가중치에서 엔지니어의 EQ와 레벨을 얻고, K-weighting 근사로 리드 보컬 대비 LU를 계산합니다. 여러 곡은 중앙값으로 합칩니다. 활성 프로필은 프로세스 전역 `shared_ptr`(atomic)에 있고, `GainBalancer::targetOffsetLu`·`referenceCurve`·기본 레퍼런스가 이 값을 먼저 확인합니다.

`StyleAnalyzer`는 조각 단위로 분석하므로 곡 길이와 무관하게 메모리가 일정합니다(10분에 약 5 KB의 100 ms 블록).
- 디코딩: JUCE 기본 포맷, macOS·Windows는 OS 디코더(m4a/mp4/mov). 그 밖의 영상은 로컬 ffmpeg 파이프(f32le)로 읽고 디스크에 쓰지 않습니다.
- 매칭: 10개 대역 편차 상위 3개를 60%만 EQ로 교정하고(±4 dB), 크레스트 차이로 버스 압축, LUFS 차이로 리미터 입력, 폭 차이로 이미저를 조정합니다.
- 악기별 기본 스타일: 레퍼런스의 기울기(밝기), PLR(리미팅), 트랜지언트, 폭, 서브 비중으로 정합니다.

## 8. 기록 (요구사항 11)

`MixHistory`는 스냅샷마다 채널별 체인 uid, 바이패스, 파라미터 값을 저장하고, 플러그인 상태 전체는 해시로 중복을 제거해 memopro에 둡니다(최대 200개).
- 되돌리기: 체인이 같으면 파라미터와 게인만 복원 한계로 되돌립니다. 체인이 다르면 저장된 상태로 체인을 다시 불러옵니다. 보호된 채널과 플러그인은 되돌리지 않습니다.
- 프로젝트 저장: 각 인스턴스가 자기 채널 몫(최근 40개)을 상태에 넣고, 불러올 때 허브가 다시 합칩니다.
- 자동 믹스 단계는 30초에 한 번만 기록합니다.

## 9. 다중 프로세스 연결 (`SessionLink`)

DAW가 일부 플러그인을 별도 프로세스에서 실행해도 인스턴스끼리 연결되도록, 이 컴퓨터 안에서만 쓰는 로컬 소켓으로 세션을 공유합니다.

- **역할 나누기**: 처음 실행된 프로세스가 `127.0.0.1:47821`(설정 `linkPort`)에서 중계를 맡고, 나머지 프로세스는 거기에 접속합니다. 중계 프로세스가 사라지면 1초 안에 다른 프로세스가 중계를 이어받습니다.
- **세션 구분**: 세션 키(`linkSession`)가 같은 프로세스끼리만 연결됩니다.
- **상태 공유**: 프로세스마다 자기 채널을 1초마다 발행합니다(`smix::wire::channelToJson`). 발행 내용은 특징, 체인, 믹스에 중요한 파라미터예요. 값 곡선(ValueMapper)은 크고 바뀌지 않으므로, 슬롯이 바뀌었거나 새 프로세스가 들어왔을 때만 보내고 받는 쪽이 캐시합니다.
- **원격 채널 반영**: `SessionHub::refresh`가 원격 채널을 세션에 합칩니다. 그래서 범위 규칙, 자동 믹스, AI 문맥에 원격 채널도 그대로 들어갑니다. 원격 버스도 부모로 인식하고, 원격 버스가 자동 믹스를 켜 두면 그 아래 채널은 그 버스가 관리하는 것으로 봅니다.
- **원격 채널 변경**: 실행기(`ActionExecutor`)는 범위 안에서 행동을 검증하고 단위를 변환합니다. 그다음 컨트롤러가 원격 채널 대상 명령을 저수준 호출(`set_param`, `set_gain`, `set_bypass`, `set_chain`, `move_slot`)로 바꿔, 그 채널을 가진 프로세스로 보냅니다.
- **테스트**: 통합 테스트가 실제 두 번째 프로세스(`SmxLinkPeer`)를 띄워서 원격 채널이 세션에 들어오는지, 변경이 전달되는지 확인합니다.

## 10. 내장 처리기 (`smix::dsp`)

순수 C++ 처리기 9종입니다. Gain, Gate, EQ(RBJ 바이쿼드), De-Esser(LR4 대역 분할), Compressor(로그 영역 피드포워드, 소프트 니), Saturation(2배 오버샘플링), Enveloper(빠른/느린 엔벨로프 비교), Reverb(8라인 FDN, Householder 행렬), Limiter(룩어헤드)가 있어요.

- **파라미터**: 실제 단위로 정의합니다(`ParamSpec`). 노브 곡선(skew)은 JUCE와 같은 식을 씁니다.
- **플러그인 연결**: `BuiltinFormat`(JUCE `AudioPluginFormat`)이 처리기들을 "SoundManager" 형식의 플러그인으로 등록합니다. 그래서 체인 계획, 조절, 기록, 절전, 보호가 서드파티 플러그인과 같은 경로로 동작합니다.
- **지식 등록**: 프로파일러가 측정한 결과에, 처리기를 만들 때부터 알고 있는 의미(한국어 설명, 범위)를 덧붙여 지식 베이스에 넣습니다.

## 11. 처리 방식 학습 (`style::learnProcessing`)

원본(raw)과 처리본(processed)에서 엔지니어의 인서트 체인을 추정합니다.

1. **정렬**: 상호상관으로 플러그인 지연을 찾습니다.
2. **EQ**: 프레임마다 레벨에 무관한 1/3옥타브 톤 변화를 구하고 그 중앙값을 냅니다. 이 곡선에 로우컷, 셸프, 피크 4개, 하이컷을 그리디 탐색으로 맞춥니다.
3. **시뮬레이션 매칭**: 가장 활발한 24초 구간에서 처리기별로 후보를 시도합니다. 후보를 내장 처리기로 원본에 렌더링하고 처리본과 비교해요.
   - **컴프**: 스레숄드 → 비율 → 어택·릴리즈 → 미세 조정 순서로 좌표 탐색합니다. 지표는 10 ms 레벨 오차입니다.
   - **게이트**: 조용한 구간이 추가로 줄어든 양을 봅니다.
   - **디에서**: 치찰 프레임의 고역 비율이 추가로 줄어든 양을 봅니다.
   - **새츄레이션**: 블록 정규화 코히어런스로 "선형으로 설명되지 않는 에너지"를 재고, 같은 지표를 드라이브별로 보정해 비교합니다.
   - **엔벨로퍼**: 어택(0~15 ms)과 서스테인(60~200 ms) 구간의 레벨 차이를 봅니다.
   - **인서트 리버브**: 소스가 멈춘 뒤의 꼬리 에너지를 봅니다.
4. **리턴 리버브**(`learnReturn`):
   - 길이: 소스가 모두 조용한 구간에서 리턴이 줄어드는 기울기로 RT60을 잽니다.
   - 센드 양: 트랙 에너지를 감쇠 커널로 번지게 한 뒤 NNLS로 각 트랙의 기여를 구합니다. 리턴의 5% 미만만 설명하는 트랙은 센드가 없는 것으로 봅니다.
   - 변환: 센드 양을 같은 젖은/마른 비율을 내는 인서트 믹스 값으로 바꿉니다.
5. **장르 프로필로 합치기**: 같은 역할의 여러 트랙을 중앙값으로 합칩니다(EQ는 중앙값 곡선에 다시 맞춤). 이 결과를 `ChainPlanner`(어떤 처리기를 넣을지)와 `RecipeEngine::learnedSettings`(시작값)가 씁니다. 스레숄드는 채널 라우드니스 기준 상댓값으로 적용합니다.
